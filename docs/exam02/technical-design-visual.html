ModDeck technical design

Real-time interactive presentation platform for KMUTT classrooms. This page is a visual guide to docs/exam02/technical-design.md: Release 1 "Foundation & Core Interactions" (features F1–F14, due 30 Nov 2026). Every choice links back to a spike result in section 6.

300students per room, one api instance
p95 ≤ 73.5 msMD-8 load test, API under 26% of one core
36 / 36reconnect tests passed (MD-13)

Design in 30 seconds

Shape

Modular monolith. One NestJS api (REST, Socket.IO and the PDF import job). Shared PostgreSQL and Redis. No microservices.

Real time

Redis holds live answers (Lua script, 22–32 µs per submit). A flusher copies them to PostgreSQL every second. Clients recover from drops with hello / sync / seq.

Frontend

Next.js 16 + React 19 + Tailwind 4. Token-based components, Zustand for live state, TanStack Query for REST data. One component renders on phone, presenter and projector.

Delivery

Docker Compose, images built on the VM. PR runs CI on GitHub. Merge to main or dev triggers a self-hosted runner deploy with smoke test and rollback.

Known R1 risks (details in 1.6)

Self-signed TLS (warnings on phones, blocks the PowerPoint add-in later) · no database backup · no monitoring · dev and production share one VM · single host.

1.5 CI/CD pipeline

CI runs on GitHub-hosted runners for every PR. The self-hosted runner only deploys: it builds on the VM, migrates, restarts, smoke-tests. No image registry.

Security: public repo + self-hosted runner

GitHub advises against this combination. Deploy job must use only on: push to protected branches, never pull_request. Require approval for outside-collaborator workflows. Run the runner as non-root.

  • Rollback needs the previous commit's image. Keep the last few SHA-tagged images, prune older ones.
  • A data-changing migration cannot be undone by image rollback. Write migrations expand first, contract later.
  • The CI job already exists. The deploy job is new.

Section 2

Frontend: component design

2.1 Principles

Atomic layers

Tokens → UI primitives → domain components → screens. A layer only uses layers below it.

One style source

Figma variables = Tailwind tokens in globals.css. Never raw hex.

Presentational vs container

Domain components take props and raise events. Screens connect store and socket. PollChart works on all three surfaces.

Server is truth

Snapshot + numbered events. UI never shows "Answer sent" before server ack.

Open for extension

R2 Live Quiz = register one new type in ActivityRenderer. No screen change.

Mobile first, projector aware

Light theme, 44×44 px targets, Thai line height, colour + letter on charts.

Section 5

Live state and real-time flow

5.1 Two stores, two jobs

Redis live, in memory, AOF

Answers of open activities, counts, seq event log, presence, Socket.IO Pub/Sub. Takes 300 answers in one second without a DB bottleneck or race (Lua script 22–32 µs per submit).

PostgreSQL durable

Everything in section 4. Results, history, export. Filled from Redis by a batch flush.

5.2 Redis keys

All keys of one session share the hash tag {sid} (one Redis Cluster slot).

KeyTypeContentWritten with
ans:{sid}:<runId>hashparticipant → option(s)HSETNX in Lua
votes:{sid}:<runId>hashoption → countHINCRBY in Lua
flush:{sid}streamone entry per accepted answerXADD in Lua
aid:{sid}hashanswerId → result (idempotent retry)Lua
log:{sid}list / streamlast 500 server events with seqevery broadcast
seq:{sid}stringlast seqINCR
presence:{sid}sorted setparticipant → last seenheartbeat
Needs a test before R1: "allow answer change"

MD-9 tested only "first answer wins" (HSETNX). With the option on, the Lua script must atomically read the old answer, decrement the old option, increment the new one and write the new answer. The flush must then delete and insert that participant's rows in one transaction instead of ON CONFLICT DO NOTHING. This path has no concurrency test yet.

5.3 Vote path

Safety nets

On "Close activity" the UI shows closed only after the final flush returns (MD-9 §7.3). If Redis loses data, the API rebuilds the session keys from PostgreSQL before accepting new answers (MD-9 §7.6).
